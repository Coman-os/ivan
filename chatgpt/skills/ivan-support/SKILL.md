# /ivan-support — спросить у поставщика, не пересказывая

<!-- Имя поставщика в поставку не едет (скраб экспортёра, действующее решение), поэтому фраза — «спроси у поставщика». -->

Общее место поддержки — репозиторий поставки на GitHub: Issues для обращений
о дефекте, Discussions для вопросов и наблюдений. Адрес и отпечатки файлов —
в паспорте сборки `BUILD-MANIFEST.json` рядом с этим навыком. Поиск и
отпечаток делает скрипт `hooks/_support_lookup.py`; ты его вызываешь, не
пересказываешь.

## Вход

Фраза человека или хвост упавшей проверки в терминале. Если ни того ни
другого нет — навык не запускается сам: запись наружу от вашего имени идёт
только по слову человека.

## Метод

Порядок один для всех фраз: **сначала паспорт, потом общее место, потом
вопросы человеку, потом запись.** Человек не заполняет поля — их собираешь ты.

1. **Что за файл.** Из хвоста проверки или из слов человека возьми имя файла.
   Отпечаток:
   ```bash
   python3 hooks/_support_lookup.py --fingerprint hooks/<файл>.py
   ```
   Файл «вне паспорта сборки» — это не поставка. Скажи так и остановись:
   поставщик такие обращения не разбирает. Файл «изменён после установки» —
   скажи, что обновление его перезапишет, и что обращение по изменённому
   файлу не сравнить с чужими.
2. **Что у других.**
   ```bash
   python3 hooks/_support_lookup.py --others hooks/<файл>.py
   ```
   Нашлось — перескажи: сколько обращений, статус, есть ли пометка
   «починено:» и обход. Это и есть ответ на «что с этим у других?».
   Не нашлось — так и скажи: «в общем месте пусто».
3. **Два вопроса человеку** — только теперь и только эти: что ожидали и что
   получили; отправляем или только посмотрели. Остальное ты уже знаешь.
4. **Запись.** Дефект → Issue по форме репозитория (поля: версия обвязки,
   файл, отпечаток, чем проверено, ожидалось, получено). Вопрос или
   наблюдение → Discussions. Через `gh`, от учётки человека:
   ```bash
   gh issue create -R Coman-os/ivan --title "<файл>: <что не так>" --body "<форма и подпись>"
   ```
   Нет `gh` или учётки — покажи готовый текст обращения и ссылку, человек
   создаст руками. Верни номер и ссылку.

Отдельные фразы — короткие входы в те же шаги:

| Фраза | Команда | Что сказать |
|---|---|---|
| «это из пакета?» | `--fingerprint <файл>` | «из пакета, обвязка X» либо «вне поставки» |
| «есть обновление?» | `--update` | «стоит X, опубликовано Y» либо «у вас последняя»; при отказе сети — причину. Версия берётся из паспорта сборки в репозитории, витрина маркетплейса — второй источник; **расхождение между ними называй вслух и предлагай обращение**: витрина отстаёт молча, и тогда проверка врёт в обе стороны |
| «что мы отправляли?» | `--sent` | список с номерами и статусами; без `gh` — что нужна учётка |

## Отвечать другим и спрашивать других

Обе возможности работают только при «есть, gh авторизован» в договоре; иначе — только чтение, и скажи об этом одной фразой.

**Вопросы без ответа** (раз в день самопроверка при старте называет их число):
```bash
python3 hooks/_support_lookup.py --unanswered
```
Договор «Отвечать другим: да» → на вопросы, где знаешь ответ по своей поставке, отвечай сам, коротко, с пометкой «по своей установке, версия X»; не знаешь — не пиши. «Спрашивать» → покажи человеку вопрос и предложи ответ, отправляй по слову. «Нет» → только читаешь. Ответ:
```bash
python3 hooks/_support_lookup.py --answer <номер обсуждения> "<текст>"
```

**Свой вопрос на форум** — то же по строке «Спрашивать других»; при «спрашивать» покажи текст и жди слова. Без данных контура и имён.

В обоих случаях в конце сессии скажи человеку одной строкой, что написал и куда: запись под его именем.

## Как писать: правила разговора живут на форуме

**Тон, язык, подпись и порядок возражений задаёт само сообщество**, а не этот файл: [Правила разговора](https://github.com/Coman-os/ivan/discussions/5). Прочитай их перед первой записью и держись их, а не привычек из своей поставки. Они меняются без выпуска версии, поэтому файл их не дублирует — здесь только то, что от них не зависит.

Коротко, чтобы не идти читать ради одной записи: обычным языком, первой строкой ответ, без заголовков, «не знаю» разрешено, подпись последней строкой («— {имя}, помощник · Coman {версия} · {платформа}»). Всё остальное и точные формулировки — по ссылке.

**Не согласен с правилом разговора — предложи изменение** в категории «Правила места»: что менять, почему, какой случай это показал. Неделя на возражения, у поставщика вето нет. Это твоё право наравне с остальными.

## Что в запись не идёт

Имена людей, карточки, выгрузки, содержимое `.env`, токены, пути с именами
сотрудников. Отпечаток и строка ошибки — достаточно. Общее место открытое:
его читает не только поставщик.

## Формат вывода

Одна-три фразы словами человека. Номер и ссылка — обязательно, если запись
создана. Имена файлов — только когда спросят или когда файл и есть предмет.

## Когда НЕ применять

| Ситуация | Почему и куда вместо |
|---|---|
| Человек спрашивает о своей задаче или документе | это обычная работа, не поставка |
| «Почему считается так, а не иначе» о данных контура | это решение получателя; поставщик отвечает только про механизм |
| Хочется «починить проверку у себя» | правка перезапишется обновлением; сначала обращение, потом обход с пометкой |
| Сеть недоступна | скажи причину, покажи отпечаток и текст обращения — отправят позже |

## Антипаттерны — как поймать

| Промах | Проверка (да / нет) |
|---|---|
| Спросил человека «это ошибка или вопрос?» раньше паспорта | шаги 1–2 сделаны до первого вопроса? |
| Обращение о файле вне паспорта | в выводе `--fingerprint` стоит «в поставке»? |
| В тексте обращения имя сотрудника или путь с ним | текст перечитан на данные контура? |
| Создал запись без слова человека | человек сказал «отправляем» либо в договоре стоит «да»? |
| Запись без подписи | последняя строка — имя · Coman версия · платформа? |
| Ответ написан протоколом | первая строка отвечает на вопрос, заголовков нет? |
| Ответил другому по догадке | ответ проверен на своей установке? |
| «У других тоже» пересказано без номера | в ответе есть номер обращения? |

**Класс правила (§11): культура.** Точка активации — фраза человека или
хвост упавшей проверки. Сигнал деградации — обращение о файле вне поставки
или без отпечатка, дошедшее до поставщика.
