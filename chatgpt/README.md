# Иван — установка в ChatGPT Work

**Версия:** 2.5.3 · журнал изменений — [CHANGELOG.md](https://github.com/Coman-os/ivan/blob/main/CHANGELOG.md)

## С чего начать
Пошаговая установка через приложение — **[START-HERE.md](START-HERE.md)**:
приложение → локальная папка-проект → маркетплейс → подтверждение проверок →
новая задача → проверка → знакомство. Ниже — устройство пакета и запасные пути.

## Что внутри
- `.codex-plugin/plugin.json` — манифест плагина.
- **7 навыка** (`skills/`) — устанавливаются вместе с плагином.
- **8 проверок качества** — объявлены в `hooks/hooks.json`, исполняет Codex
  после подтверждения (см. ниже). Ровно столько строк вы увидите в настройках хуков.
- `hooks/secret-scan.py` — сканер секретов для git. Не проверка Codex, а утилита:
  ставится отдельно в `.git/hooks/`, Иван объяснит при знакомстве.
- **Правила Ивана целиком** (`skills/ivan-rules/`) — грузятся при старте каждой
  сессии проверкой «Загрузка правил Ивана», а не по требованию.
- `detect-python.py` — диагностика Python, только чтение. Ивана просят «проверь
  Python», сам он запускает этот скрипт; руками ничего делать не нужно.
- **8 файлов знаний** (`knowledge/`) — принципы и стандарты.
- `instructions.txt` — сжатая выжимка правил для **другого продукта**: обычного
  ChatGPT с custom GPT, где плагинов нет (см. последний раздел).

Что нужно на компьютере: Python 3.10 или новее («три точка десять», не 3.1).
Библиотек ставить не надо.

## Установка из командной строки (запасной путь)
Основной путь — через приложение, он в START-HERE.md. Командная строка нужна,
только если в приложении недоступно добавление маркетплейса:
```
codex plugin marketplace add https://github.com/Coman-os/ivan --ref main
codex plugin add coman-ivan-codex@coman
```
Навыки становятся доступны **со следующей сессии** — начни новую после установки.

Проверки и правила приезжают вместе с плагином: `hooks/hooks.json` внутри
пакета Codex находит сам. **Ничего никуда копировать не нужно** — ни в
`~/.codex/hooks.json`, ни в папку проекта. Копия создаёт дубли: в настройках
появятся «Иван» и ещё столько же одинаковых пользовательских хуков.

## Поддержка

Общее место — репозиторий поставки: [обращения о дефектах](https://github.com/Coman-os/ivan/issues) по форме и [форум](https://github.com/Coman-os/ivan/discussions) для вопросов и наблюдений. Оно открытое: данные вашего контура туда не идут. Скажите помощнику «спроси у поставщика» — он возьмёт отпечаток файла из паспорта сборки, посмотрит, известно ли это другим, задаст два вопроса и оформит запись. Другие фразы: «это из пакета?», «что с этим у других?», «есть обновление?», «что мы отправляли?». При старте сессии помощник сам сообщает, есть ли открытые обращения на вашу версию; при падении проверки — печатает отпечаток и адрес.

## Проверки качества
**Подтверждение.** Codex не запускает проверку, пока человек не подтвердил её
в настройках хуков (в приложении — Настройки → Хуки; в консоли — `/hooks`).
Установка плагина подтверждением не считается, и о неподтверждённой проверке
Codex не сообщает — она просто молчит. Подтверждение привязано к содержимому
файла: **после обновления поставки его надо дать заново**.

**Что видно из сессии, а что нет.** Диагностика при старте видит файлы и их
объявление в конфиге. Подтверждены ли проверки и срабатывают ли они на
событии — из сессии не видно. Единственное доказательство — событие: попросите
Ивана создать документ без карточки назначения, и замечание должно прийти.
«Готово» означает наблюдавшееся событие, а не «скрипты лежат на месте».

**Что проверка может, а что нет.** Проверка после записи приходит **после**
записи: файл на диске уже есть, Иван получает замечание и исправляет. Часть
действий проходит мимо проверок — документация Codex называет их «полезным
ограждением, а не полным рубежом». Без подтверждённых проверок правила остаются
текстом: Иван будет им следовать, но следование вероятностно.

**Если экран хуков пуст.** Сначала проверьте, что добавлен локальный проект
(папка на компьютере в списке проектов): без него список хуков не запрашивается.
Это не отсутствие Python и не отсутствие доверия.

## Другой продукт: обычный ChatGPT без плагинов
Это **не** установка в Codex — отдельный сценарий для рабочего пространства, где
плагины недоступны:
1. **Создать custom GPT** (GPT Builder → Configure).
2. **Instructions:** открой `instructions.txt`, скопируй весь текст в поле «Instructions».
3. **Knowledge:** загрузи файлы из `knowledge/` в раздел «Knowledge».
4. **Skills:** если рабочее пространство поддерживает Skills — загрузи папки из `skills/`.

Проверок качества в этом сценарии нет: их исполняет Codex, а не custom GPT. В
поле Instructions влезает только выжимка правил.

## Что проверить в тесте
- Дай задачу с неоднозначностью → уместно ли Иван уточняет (не молча угадывает)?
- Дай задачу оформить документ → следует ли структуре/языку/метаданным?
- Спроси «почему так вышло» → отвечает ли по формату (Где сбой / Почему / Что починить)?
- Дай факт, которого нет в источнике → не выдумывает ли, помечает ли TBD?
