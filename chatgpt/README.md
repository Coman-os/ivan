# Иван — установка в ChatGPT Work

**Версия:** 2.2.0 · журнал изменений — [CHANGELOG.md](https://github.com/Coman-os/ivan/blob/main/CHANGELOG.md)

## Что внутри
- `.codex-plugin/plugin.json` — манифест плагина.
- **6 навыка** (`skills/`) — устанавливаются вместе с плагином.
- **9 проверок качества** (`hooks/` + `hooks/hooks.json`) — исполняются, см. ниже.
- **Правила Ивана целиком** (`skills/ivan-rules/`) — грузятся при старте каждой
  сессии хуком, а не по требованию.
- `instructions.txt` — сжатая выжимка правил для **ручной** установки в поле
  Instructions (туда влезает лишь часть свода).
- **8 файлов знаний** (`knowledge/`) — принципы и стандарты.

## Установка плагином (консольный Codex)
```
codex plugin marketplace add <репозиторий-поставки> --ref main
codex plugin add coman-ivan-codex@<имя-маркетплейса>
```
Навыки становятся доступны **со следующей сессии** — начни новую после установки.

Проверки качества и правила приезжают вместе с плагином и регистрируются сами:
`hooks/hooks.json` внутри пакета Codex читает без ручных шагов.

**Правила грузятся каждую сессию.** Хук старта кладёт полный свод в контекст —
не выжимку и не по запросу. Подтвердите его вместе с остальными (см. ниже):
без подтверждения Иван будет знать лишь то, что вы вставили в поле Instructions.

## Установка вручную (приложение ChatGPT)
В приложении git-установки нет — плагин ставят из каталога либо из маркетплейса
рабочего пространства, который подключает администратор. Если ни того ни другого
пока нет, разверни вручную:
1. **Создать custom GPT** (GPT Builder → Configure).
2. **Instructions:** открой `instructions.txt`, скопируй весь текст в поле «Instructions».
3. **Knowledge:** загрузи файлы из `knowledge/` в раздел «Knowledge».
4. **Skills:** если рабочее пространство поддерживает Skills — загрузи папки из `skills/`.
5. **Проверки качества и правила** — скопируйте в проект:
   - папку `hooks/` целиком → `<проект>/.codex/hooks/`
   - файл `hooks/hooks.json` → `<проект>/.codex/hooks.json` (на уровень выше!)

   Путь `hooks/hooks.json` работает только внутри установленного плагина. Для
   проектной установки Codex ищет конфиг в `.codex/hooks.json` либо в секции
   `[hooks]` файла `.codex/config.toml` — вложенный `.codex/hooks/hooks.json`
   он не найдёт.

   В скопированном `hooks.json` замените `$PLUGIN_ROOT/hooks/` на реальный путь
   к папке со скриптами, например `.codex/hooks/`: переменную `PLUGIN_ROOT`
   Codex выставляет только для хуков плагина.

При ручной установке в поле Instructions влезает только выжимка правил. Полный
свод приходит хуком старта сессии — он же и есть причина ставить `hooks/`.

При ручной установке `knowledge/` работает только как загруженные файлы GPT:
сам Codex этот каталог не подхватывает, ссылки на принципы идут из навыков.

## Проверки качества
Документ без таблицы метаданных не сохранится, англицизмы в клиентском тексте
заблокируются, запись в память потребует пройденной лестницы мест. Это не
подсказка модели — это отказ записи.

**Подтверждение при первом запуске.** Codex не запускает проверку, пока человек
не подтвердил её (команда `/hooks`). Установка плагина подтверждением не
считается. Подтверждение привязано к содержимому файла: **правишь скрипт —
подтверждение слетает, и проверка молча перестаёт работать**. После любой
правки подтверди заново.

**Чего платформа не гарантирует.** Часть действий проходит мимо проверок —
документация Codex называет их «полезным ограждением, а не полным рубежом».
Проверка ловит обычный путь записи, не все возможные.

Без подтверждённых проверок правила остаются текстом инструкции: Иван будет им
следовать, но следование вероятностно, а не гарантировано отказом.

## Что проверить в тесте
- Дай задачу с неоднозначностью → уместно ли Иван уточняет (не молча угадывает)?
- Дай задачу оформить документ → следует ли структуре/языку/метаданным?
- Спроси «почему так вышло» → отвечает ли по формату (Где сбой / Почему / Что починить)?
- Дай факт, которого нет в источнике → не выдумывает ли, помечает ли TBD?
