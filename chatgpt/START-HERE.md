# Иван в Codex — установка через приложение

> **Кому это.** Вам передали Ивана и вы ставите его себе. Терминал не понадобится: всё делается в приложении и в диалоге с Иваном.
>
> **Что такое Иван.** Помощник, который уточняет, когда непонятно; сам делает то, что может решить, и не дёргает по мелочам; возражает, когда видит проблему, вместо того чтобы молча выполнить.
>
> **Что нужно на компьютере.** Python 3.10 или новее — «три точка десять», не 3.1. Проверять его будет Иван, а не вы (шаг 4).

Поставка 2.5.4. Маршрут снят с реальной установки на macOS; для Windows отдельного прогона не было.

---

## Шаг 1. Приложение и вход

Скачайте приложение с официальной страницы OpenAI и войдите в аккаунт. В переключателе продукта (название в левом верхнем углу) выберите **Codex**.

![Нажмите название продукта в левом верхнем углу и выберите Codex](https://raw.githubusercontent.com/Coman-os/ivan/main/docs/img/01-vybor-codex.png)

*Переключатель продукта: ChatGPT → Codex.*

**Результат:** открыто приложение в режиме Codex. Если режима нет, проверьте актуальность приложения и доступ аккаунта — установка Ивана этого не исправит.

## Шаг 2. Локальная папка как проект

Создайте на компьютере папку для работы, например «Документы → Иван». В боковой панели Codex: **Создать проект → Локальный → Далее**, выберите эту папку.

Нужна именно папка **на компьютере**, добавленная в список проектов. Облачный проект и папка, которую приложение создаёт для отдельного чата, — другие вещи.

![Создать проект → Локальный → Далее](https://raw.githubusercontent.com/Coman-os/ivan/main/docs/img/02-lokalnyy-proekt.png)

*Тип проекта — «Локальный», затем выбор папки на компьютере.*

**Результат:** проект с вашей папкой виден в боковой панели.

> Без локального проекта вкладка «Хуки» в настройках остаётся пустой: список проверок не запрашивается. Пустой экран на этом шаге — не поломка Ивана и не отсутствие Python.

## Шаг 3. Маркетплейс и установка

**Настройки → Плагины → Добавить → Добавить маркетплейс.** Заполните форму:

| Поле | Что указать |
|---|---|
| Источник | `https://github.com/Coman-os/ivan` |
| Git ref | `main` |
| Выборочные пути | оставьте пустым (серый текст в поле — подсказка, не значение) |

![Настройки → Плагины → Добавить → Добавить маркетплейс](https://raw.githubusercontent.com/Coman-os/ivan/main/docs/img/03-dobavit-marketplace.png)

*На снимке Иван уже установлен; у нового пользователя списка с ним ещё не будет.*

![Окно добавления источника](https://raw.githubusercontent.com/Coman-os/ivan/main/docs/img/04-forma-istochnika.png)

*Серый текст в полях — подсказки, а не заполненные значения.*

Нажмите «Добавить маркетплейс», затем «Просмотреть каталог». Найдите источник **coman** и плагин **«Иван» для Codex** (техническое имя `coman-ivan-codex`). Откройте карточку и установите. В списке установленных переключатель Ивана должен быть включён.

Версия для Claude / Cowork — другой пакет в том же источнике; ставить нужно только один.

**Результат:** в установленных плагинах есть включённый «Иван» из источника coman. Если плагин не появился — закройте приложение полностью (⌘Q) и откройте снова.

<details>
<summary>Запасной путь: командная строка</summary>

Нужен только если добавление через приложение недоступно. Откройте Терминал и проверьте:

```
codex --version
```

Если версия показана:

```
codex plugin marketplace add https://github.com/Coman-os/ivan --ref main
codex plugin add coman-ivan-codex@coman
```

Если «command not found: codex» — исполняемый файл на Mac лежит внутри приложения: `"/Applications/ChatGPT.app/Contents/Resources/codex"`. Подставьте этот путь вместо `codex`. Файла нет — используйте официальную инструкцию установки командной версии, не создавайте файл по отсутствующему пути.

## Шаг 4. Попросите Ивана проверить Python

Откройте задачу в добавленном проекте и отправьте:

```
Иван, проверь, есть ли на компьютере рабочий Python 3.10 или новее. Сам выполни проверку версии и короткий запуск кода. Пока ничего не устанавливай и не меняй. Подходит — скажи одной строкой. Не подходит — объясни простыми словами, что установить, и дай официальную ссылку. Если проверка недоступна из-за ограничений, не называй это отсутствием Python.
```

Иван запускает диагностику сам. Если приложение спросит разрешение на запуск — просмотрите и разрешите.

Возможные ответы: подходящий Python найден · Python есть, но старый (нужно обновить) · не найден (Иван скажет, что поставить и откуда) · проверить не удалось из-за ограничений (это не «нет Python»).

Если Python нужно поставить: официальный установщик с python.org, после установки перезапустите приложение и напишите «Проверь Python ещё раз».

**Результат:** Иван назвал найденную версию и подтвердил выполнение кода. Это проверка из диалога; автоматический запуск проверок подтверждается на шаге 6.

## Шаг 5. Подтвердите 8 проверок

**Настройки → Хуки → Из плагинов → Иван.** Должен быть один источник «Иван» и 8 проверок: четыре после записи файла, две при старте сессии, две перед завершением ответа.

![Правильный список: один источник «Иван» и восемь хуков](https://raw.githubusercontent.com/Coman-os/ivan/main/docs/img/05-spisok-hukov.png)

*Нажмите строку, чтобы открыть проверки.*

Если возле проверки есть кнопка **Trust / «Доверять»** — просмотрите команду и подтвердите. Убедитесь, что переключатели включены.

Надпись «Все проекты» означает общий источник плагина: для новой папки ничего повторно копировать не нужно. Названия «Хук 1», «Хук 2» — особенность интерфейса, не ошибка установки; раскройте строку, чтобы увидеть команду и подпись.

![Штатный набор: «Иван → Все проекты», восемь включённых проверок](https://raw.githubusercontent.com/Coman-os/ivan/main/docs/img/06-vklyuchennye-proverki.png)

*Так выглядит правильно настроенный набор.*

**Результат:** один набор «Иван», 8 включённых проверок, запросов доверия не осталось.

> **Подтверждение слетает после обновления поставки.** Обновили Ивана — зайдите сюда снова и подтвердите изменённые проверки, затем начните новую задачу.

## Шаг 6. Новая задача и проверка запуска

Создайте **новую** задачу в локальном проекте — после подтверждения: загрузка правил происходит при старте сессии. Отправьте:

```
Проверь установку Ивана. Создай через apply_patch временный Markdown-документ без карточки назначения и проверь автоматическую реакцию проверки. Затем исправь документ и удали пробный файл. Отдельно сообщи, подтверждена ли загрузка правил при начале сеанса. Не выдавай ручной запуск Python за автоматическое срабатывание.
```

Должно прийти замечание о документе без карточки; после исправления оно не повторяется. Отчёт Ивана обязан различать три вещи: сработало · ошибка · проверить не удалось.

![Результат реального теста](https://raw.githubusercontent.com/Coman-os/ivan/main/docs/img/07-rezultat-testa.png)

*Python 3.14.3 работает, проверка карточки документа сработала автоматически.*

**Результат:** замечание наблюдалось. Этим подтверждена одна проверка из 8: та, что смотрит карточку документа. Остальные срабатывают на своих событиях по ходу работы; «Иван работает» означает наблюдавшееся событие, а не «файлы на месте».

## Шаг 7. Знакомство

Напишите: **«Давай настроим Ивана»** или `/ivan-setup`. Расскажите, чем занимаетесь и какую работу хотите поручать. Иван предложит структуру папок и запишет договор в `WORKING-AGREEMENT.md` в рабочей папке.

Пока договор не заполнен, Иван работает вполсилы: о вас он не знает ничего и переспрашивает на каждом шаге. Это лечится один раз, за 10–15 минут.

Плагин доступен во всех ваших локальных проектах, а договор живёт в конкретной папке — в другой папке его нужно заполнить снова или скопировать.

**Готово к работе:** плагин включён, проверки подтверждены, событие наблюдалось, договор записан. Дайте Ивану настоящую задачу.

## Как обновлять

Иван обновляется как любой плагин, договор и ваши файлы при этом не трогаются.

1. Спросите Ивана «есть обновление?» — он сравнит свою версию с последней и скажет, что изменилось. Или посмотрите журнал: [CHANGELOG.md](https://github.com/Coman-os/ivan/blob/main/CHANGELOG.md).
2. В приложении: **Настройки → Плагины → Иван → обновить** (маркетплейс тот же, ref `main`). В консоли: `codex plugin marketplace update coman` и затем `codex plugin add coman-ivan-codex@coman`.
3. **Подтвердите проверки заново** (шаг 5): подтверждение привязано к содержимому файлов и слетает при каждом обновлении. Пока не подтвердили — проверки не работают, и Иван не знает своих правил.
4. Начните новую задачу: версия применяется при старте.

Если после обновления активная сессия зовёт удалённые файлы, вы увидите `can't open file`. Это не провал установки: закройте приложение через ⌘Q и начните новую задачу.

![Пример ошибки старой сессии после обновления](https://raw.githubusercontent.com/Coman-os/ivan/main/docs/img/08-oshibka-staroy-sessii.png)

*Реальный случай обновления 2.4.0 → 2.5.1: старая сессия обращается к файлам прежней версии.*

**Что переживает обновление:** договор пары, ваша рабочая папка, имя Ивана. **Что перезапишется:** любые правки внутри папки плагина. Нужна своя правка — сначала обращение к поставщику («спроси у поставщика»), потом обход с пометкой.

## Если что-то не так — скажите «спроси у поставщика»

Общее место поддержки — этот же репозиторий: [обращения о дефектах](https://github.com/Coman-os/ivan/issues) по форме и [форум](https://github.com/Coman-os/ivan/discussions) для вопросов и наблюдений. Место открытое: данные вашей работы туда не идут.

Выбирать не нужно. Скажите Ивану **«спроси у поставщика»** — он возьмёт отпечаток файла из паспорта сборки, посмотрит, известно ли это другим получателям, задаст два вопроса и оформит запись. Если проверка упала, он сам напишет об этом и подскажет ту же фразу.

| Фраза | Что получите |
|---|---|
| «это из пакета?» | «из поставки, версия такая-то» либо «вне поставки» |
| «что с этим у других?» | сколько получателей подтвердили, статус, починено ли |
| «есть обновление?» | что установлено, что опубликовано, что изменилось |
| «что мы отправляли?» | ваши открытые обращения с номерами |

Чтобы Иван мог писать туда, а не только читать, нужна учётка GitHub и вход в неё из консоли (`gh auth login`). Знакомство это проверяет и объясняет три шага. Без учётки он форум читает, но не пишет.

**Как здесь разговаривают.** Форма нужна только в обращении о дефекте — она экономит час на отсев «а это вообще из поставки?». Всё остальное обычный разговор, без заголовков и канцелярита. Помощники подписываются последней строкой: `— Марк, помощник · Coman 2.5.3 · Claude Code` (имя помощника · источник поставки и версия · платформа). Имени человека в подписи нет. У внешних агентов слова `Coman` не будет — по нему видно, что помощник из нашей поставки.

Правила места, что считается подтверждением и чего не писать — [прочитайте перед первой записью](https://github.com/Coman-os/ivan/discussions/2).

## Если что-то не совпало

![Так быть не должно: один и тот же набор в конфигурации пользователя и в плагине](https://raw.githubusercontent.com/Coman-os/ivan/main/docs/img/09-dubli-hukov.png)

*Дубли от ручного копирования: оставить нужно только источник плагина, пользовательские копии Ивана удалить.*


| Что видно | Что сделать |
|---|---|
| Экран хуков пуст, «хуки не найдены» | Проверьте, что добавлен локальный проект (шаг 2). Откройте вкладку заново. Не создавайте копии хуков и не копируйте файлы в настройки пользователя |
| «Иван» и ещё 8 одинаковых пользовательских хуков | Дубли от ручного копирования. Оставьте источник плагина, удалите только пользовательские копии Ивана; чужие хуки не трогайте. Удалять файлы — после завершения сессий, которые их используют |
| Переключатель недоступен | Возможно, нужно подтверждение (шаг 5). Настройки, управляемые организацией, — к администратору |
| После обновления снова просит Trust | Так и должно быть: подтверждение привязано к содержимому файлов. Подтвердите, начните новую задачу |
| Иван не знает своих правил | Загрузка правил — одна из проверок; проверьте, что она подтверждена (шаг 5), и начните новую задачу |
| Ошибка «can't open file» на старте | Активная сессия зовёт удалённый файл. Завершите такие сессии и начните новую |
| Переспрашивает по каждой мелочи | Не заполнен договор — шаг 7 |

**Если пишете о проблеме — приложите `BUILD-MANIFEST.json`** из папки плагина: по нему видно, та ли редакция приехала и всё ли доехало.

## Что этот маршрут не покрывает

- **Windows.** Инструкция снята с macOS. На Windows команды проверок зовут интерпретатор по имени `python`, и при установке из магазина приложений под этим именем может отвечать заглушка. Отдельного прогона не было — считайте установку на Windows непроверенной, пока шаг 6 не пройден там.
- **Обычный ChatGPT без плагинов.** Это другой продукт; сценарий с custom GPT описан в README пакета, проверок качества там нет.
